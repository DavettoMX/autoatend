# AutoAtend (CENEVAL Case 10433) — Architectural Baseline & Execution Plan

**Role:** Principal Software Architect / Technical PM
**Inputs:** `2907_10433.pdf` (problem statement), `TrabajoEscrito_Consolidado.pdf` (architecture baseline)
**Targets:** Windows x86-64 (i5, 8 GB, primary) · macOS 27 ARM64 (Apple Silicon M2, 8 GB, backup)

---

**Document Alignment (Step 1):** The problem statement (CENEVAL case 10433, TelArg/AutoAtend) issues five consignas that map 1:1 to the architecture baseline: **(a)** corpus DB → two SQLite 3NF files (`corpus.db`, `resultados.db`); **(b)** text analyzer → hand-built lexical pipeline (own regex parser → Thompson NFA-ε → state-set simulation → symbol table → per-lexeme regex generation, e.g. `factur(a|as|ación|ado|ando)`); **(c)/(d)** test plan + justification → 6-level verification driven by 4 algebraic invariants (I-1..I-4); **(e)** classifier web service → Go stdlib HTTP server on loopback 8471 (fallback 8472–8480) with native sparse-JSON inference. The prompt adds one new constraint not in the baseline: a **backup target macOS ARM64 (M2)**, absorbed into the cross-compilation strategy below.

### 1. Architectural Baseline & Deployment Strategy

*   **System Components:**
    1.  **Lexer / Software Base** (`internal/regex`, `internal/lexer`, `cmd/simulador`): hand-written Go chain — recursive-descent regex parser (operators `| * + ? ( ) [ ]`, AST) → Thompson construction (≤ 2·|r| states) → NFA-ε simulation via ε-closure/move in O(n·m) → Unicode NFC normalizer → 4-state DFA tokenizer → curated stoplist (homographs retained) → symbol table (hash, O(1)) → LCP-based regex generator with round-trip validation → 3-char prefix index. **No `regexp` import, no external parser generators.** Solves consigna **b**.
    2.  **Database** (`internal/db`, `cmd/gencorpus`): two SQLite 3NF files via `modernc.org/sqlite` (pure Go, zero CGo). `corpus.db` (`categorias` with CHECK of the 5 case labels, `comentarios` with FK + ISO-date GLOB, 3 indexes, plus a persisted deterministic 80/20 temporal-stratified split) seeded deterministically (seed **10433**, ~73,000 comments, distribution 30/20/20/20/10). `resultados.db` (`corridas`, `lexemas`, `frecuencias` with `categoria_id NULL` = global, `variantes`), with cross-file `categoria_id` integrity enforced via `ATTACH DATABASE` in the generation pipeline only (both files on disk); at runtime the DBs are in-memory deserialized buffers that `ATTACH` cannot target, so integrity is verified per-database (ADR-007). Solves consigna **a**.
    3.  **Web Service** (`cmd/autoatend`, `internal/web`, `internal/ml`): Go stdlib `net/http` on `127.0.0.1:8471` with automatic fallback 8472–8480; endpoints `GET /` (embedded HTML, system fonts, no CDN), `POST /api/clasificar`, `GET /api/lexemas` (paginated), `GET /api/categorias`, `GET /api/health`; native Go inference over sparse `modelo.json` (TF-IDF + NBM or Softmax LR, selected by 5-fold stratified CV Macro-F1); `--selftest` headless mode (<3 s, exit 0/1). Solves consigna **e**; consignas **c/d** are the verification protocol in §2 plus `docs/PLAN_PRUEBAS.md` (Phase 2).

*   **Cross-Compilation Plan:** Single Go module, one `./cmd/autoatend` entrypoint, only pure-Go dependencies (`modernc.org/sqlite`), all assets (`corpus.db`, `resultados.db`, `modelo.json`, UI) embedded via `go:embed`. Both binaries are produced from the same commit on any host with no C toolchain:

    ```bash
    # Primary target — Windows x86-64 (Intel i5, 8 GB)
    CGO_ENABLED=0 GOOS=windows GOARCH=amd64 \
      go build -trimpath -ldflags="-s -w -X main.version=1.0.0" \
      -o dist/autoatend.exe ./cmd/autoatend

    # Backup target — macOS 27 Golden Gate, Apple Silicon M2 (ARM64)
    CGO_ENABLED=0 GOOS=darwin GOARCH=arm64 \
      go build -trimpath -ldflags="-s -w -X main.version=1.0.0" \
      -o dist/autoatend-macos-arm64 ./cmd/autoatend
    ```

    Constraints enforced: `CGO_ENABLED=0` (eliminates DLL/ABI risk; `modernc.org/sqlite` needs no C); `-trimpath -ldflags="-s -w"` (reproducible, compact static binaries); CI grep-gate forbidding `import "regexp"` and any non-stdlib platform binding; the only `runtime.GOOS` branch permitted is the optional browser auto-launch (`rundll32 url.dll` vs `open`), guarded and non-critical; the embedded databases are loaded from `go:embed` into a `[]byte` and opened through `Deserialize` on an in-memory (`:memory:`) connection (modernc.org/sqlite `conn.go:1271–1295` — verified: `Xsqlite3_malloc64` + `copy` move the data into SQLite-managed memory before `Xsqlite3_deserialize` with `FREEONCLOSE|RESIZEABLE`, so the read-only embed bytes are only ever read), accessed via `sql.Conn.Raw` with a local interface assertion `interface{ Deserialize([]byte) error }`; the pool is pinned with `SetMaxOpenConns(1)`, `SetMaxIdleConns(1)`, `SetConnMaxLifetime(0)`, `SetConnMaxIdleTime(0)` — otherwise pool recycling closes the only connection and the in-memory database is lost; a non-nil `Deserialize` error is fatal at startup (fail fast with diagnostic); read-only enforcement moves from the file-scoped `mode=ro&immutable=1` to `PRAGMA query_only=ON` (**deviation from baseline §5.1.4/§6.1.1 — recorded as ADR-007**); loopback-only listener requires no admin rights or firewall rules on Windows or macOS; on macOS the unsigned binary may need `xattr -d com.apple.quarantine` (user-level, no admin) if transferred from another machine. Memory footprint (deserialized DBs + symbol table + sparse model in RAM, ≈ 2× DB size transient) is orders of magnitude below the 8 GB limit on both targets.

### 2. Execution Plan (WBS)

**Phase 1 — Database & Data Generation** *(consigna a)*
*   **Tasks:** Init Go module + pin deps; implement DDL/migrations for `corpus.db` and `resultados.db` per the baseline data dictionary (CHECK constraints, FK `ON DELETE RESTRICT`, composite PK in `frecuencias`, indexes) with two marked deviations: (i) `PRAGMA journal_mode=DELETE` on **both** files before `VACUUM` and embedding (**deviation from baseline Anexo I**, which sets `journal_mode=WAL` on `corpus.db` — recorded in ADR-007); (ii) partial unique index `CREATE UNIQUE INDEX uq_frecuencias_global ON frecuencias(lexema_id, corrida_id) WHERE categoria_id IS NULL;`, chosen over a sentinel value because it preserves the baseline's NULL-as-global semantics relied on by the I-2 query and the Anexo I dictionary while restoring the uniqueness that SQLite's NULL-distinct rule removes (**deviation from baseline Anexo I DDL — recorded as ADR-006**). Build `cmd/gencorpus`: `rand.New(rand.NewSource(10433))`, 30–60 slot-typed templates per category, domain vocabularies (plans, amounts, folios, colloquialisms), calibrated noise injector (missing tildes, case jitter, abbreviations `q/x/tel/fact`, typos), pre-persist validation battery (per-category counts vs target, no empty texts, bounded inter-category lexical overlap, 50-comment/category sample review); transactional bulk insert of 73,000 rows; `ATTACH DATABASE` cross-file integrity helper (generation pipeline only — runtime integrity is per-database, ADR-007); deterministic-write discipline (sorted iteration order, fixed PRAGMAs, no timestamps in `corridas`, post-build `VACUUM`) as the enabling mechanism for invariant I-3; deterministic 80/20 temporal-stratified split fixed once here — per category, `comentarios` ordered by `fecha` (ties broken by `id`), oldest 80% → train, newest 20% → test — persisted in `corpus.db` as a materialized assignment and reused unchanged by the Phase 2 gold5 candidates and Phase 3 training/evaluation (no re-splitting downstream).
*   **Deliverables:** `internal/db/` (schema, migrations, read-only opener), `cmd/gencorpus/`, populated `corpus.db` (with persisted deterministic split), generator validation report, ADR-001 (SQLite/modernc), ADR-002 (synthetic corpus design), ADR-006 (`frecuencias` global-row uniqueness fix).
*   **Testing Focus:** TDD unit tests for generator determinism (same seed → identical row set) and DDL enforcement (6th category rejected, FK restrict, date GLOB; a second global row with `categoria_id IS NULL` for the same `(lexema_id, corrida_id)` rejected by `uq_frecuencias_global`); split determinism test (same seed → identical train/test assignment; stratification within ±1%; no temporal leakage — `max(train.fecha) ≤ min(test.fecha)` per category); **Integration test (Level 4a):** gencorpus → `corpus.db` — exact target counts, distribution within ±1%, zero empty texts; groundwork for I-3.

**Phase 2 — Custom Lexical Analyzer (NFA-ε)** *(consigna b; invariants for c/d)*
*   **Tasks:** Implement in strict TDD order: regex parser (grammar `expresion→alternancia→concatenacion→factor→primario`, operators `| * + ? ( ) [ ]` plus the `\` metacharacter escape per the baseline §6.2.3 grammar — `caracter → LETRA | DIGITO | '\' metacaracter` — typed AST, descriptive errors); Thompson construction (fragment composition rules); ε-closure + move simulator; Unicode NFC lowercase normalizer with defined alphabet (`[a-záéíóúüñ]`, digits, separators); 4-state DFA tokenizer; curated stoplist hash map (documented homograph retention); symbol table with global + per-category counters and variant sets; LCP-root regex generator with alternation of suffixes; round-trip validator (re-parse generated ER → Thompson → simulate acceptance of every observed variant, fallback to canonical form on failure — target: never triggered); 3-char prefix index for candidate pruning; `cmd/simulador` sweep `corpus.db` → persist `corridas/lexemas/frecuencias/variantes` into `resultados.db`; export two separate statistic sets for Phase 3: the full-corpus sweep stats persisted in `resultados.db` (consigna b) and the train-partition document frequencies used for the model — the catalog in `resultados.db` stays built on the full corpus, but the model's vocabulary and IDF vector are computed from the training partition only; catalog terms with df=0 in training (lexemes observed only in the test partition) are excluded from the model vocabulary — consistent with fit-on-train semantics and zero parity risk — while remaining in the catalog, and their count is reported (**correction of the baseline's implicit full-corpus IDF**). Additionally: **(1)** author the stoplist as a versioned data file (`internal/lexer/stoplist/v1.json`, form → closed class) under one consistent policy covering the four classes required by the problem statement — **filtered (unambiguous):** articles: el, la, los, las, un, una, unos, unas, lo; contractions (fused article forms): al, del; prepositions: de, en, con, por, a, ante, tras, durante, mediante, según, sin, hasta, desde, contra; conjunctions: y, e, o, u, ni, que, pero, sino, aunque, porque, pues; interjections: ah, eh, ay, uf, olé — **retained homographs (not filtered):** bajo, para, sobre, entre, como, más, solo, aun, hacia (retained because the noise injector's tilde-dropping makes it confusable with hacía, imperfect of hacer). Explicit policy statements: (i) `la` and `lo` are filtered as articles; their clitic direct-object-pronoun uses are an over-filtering limitation measured in the L-1 200-token sample; (ii) `se`, `no`, `este`, `eso` — listed as filtered in baseline §5.1.2 — are **not** filtered: they do not belong to the four required classes (pronoun, adverb, demonstratives) and filtering `no` would damage classification of phrases such as "no funciona" (**deviation from baseline §5.1.2**); (iii) the retained homographs include forms that are prepositions in some contexts, and their retention is a documented, measured limitation (L-1, 200-token sample), not a claim of compliance with the "ignore prepositions" requirement for those forms. This resolves the baseline's internal contradiction: §6.2.2's stoplist omitted prepositions (now explicitly included, per the problem statement and §5.1.2) and `para` moves from §5.1.2's filtered list to the retained-homograph list (consistent with §6.2.2). Accent rule (single, explicit — restricted tilde-less variants, no folding code): `v1.json` carries explicit tilde-less variants for exactly the accented filtered forms (`según` + `segun` → preposition; `olé` + `ole` → interjection); no accent-folding logic exists anywhere in the lexer, and token normalization and symbol-table keys keep tildes. The variant list is provably exhaustive because según and olé are the only accented forms in the filtered set. Collision analysis, each case decided explicitly: `él→el`, `qué→que`, `más→mas`, `sí→si`, `té→te` — none of these occur as an effect of the rule (él, qué, sí, té are never folded and survive to the symbol table; más is in the retained set and mas is not in the filtered set, so both survive), so the restricted rule adds no over-filtering of its own. However, the corpus noise injector drops tildes from any word, so qué arrives as que and él as el and both are filtered regardless of the rule; this is documented as a corpus-level effect (not a stoplist-rule effect) and is measured in the L-1 200-token sample together with la/lo. Enumeration of the five collision cases: only qué→que and él→el cause over-filtering, both originating from the corpus noise injector's tilde-dropping and not from the stoplist rule; más→mas, sí→si and té→te cause none, because mas, si and te are not in the filtered set. Global folding was evaluated and rejected: it would extend the same over-filtering to correctly-accented él/qué occurrences — rule-level over-filtering with zero compensating benefit (**deviation from baseline**: Etapa 1 preserves tildes and §5.1.2 lists accented forms as filtered without defining any rule for tilde-less variants — recorded as ADR-008). The stoplist version is recorded in `corridas.parametros`. **(2)** Author `docs/PLAN_PRUEBAS.md`: standalone test-plan and justification document (consignas c/d) mapping each of the 6 verification levels and each quantitative threshold to its ISO/IEC 25010 subcharacteristic and its justification rationale, per TrabajoEscrito §6.3.3, §6.3.8 and Anexo II; the document is authored in Phase 2 as a complete, forward-looking document covering all 6 levels, with thresholds pinned from baseline §6.3.8. **(3)** Author the candidate gold demo comments with expected labels, drawn exclusively from the held-out test partition fixed in Phase 1 (never from training); the final 5 are frozen after Phase 3 model selection under the criterion "correctly classified by the winning model with confidence ≥ 0.80 (winning-class posterior)" — the threshold 0.80 is fixed here, in Phase 2, before freezing, so the selection is reproducible — because `--selftest` exits 1 if any gold comment is misclassified; stored as `gold5.json`, input to Phase 3's parity check and Phase 4's `--selftest` embedding. Because gold5 selection requires "correctly classified by the winning model", the `--selftest` gold check is a **regression guard** (detects model/pipeline drift between builds), not an independent accuracy test; accuracy evidence comes only from CPM01/CPM02 measured on the full test partition. **(4)** Author the L-1 measurement: 200 manually labeled tokens covering retained-homograph occurrences plus la/lo/él/qué occurrences, drawn from the test partition; report the under-filtering rate (retained forms acting as closed class) and the over-filtering rate (la/lo/él/qué acting as pronoun/interrogative) in `docs/PLAN_PRUEBAS.md`; the labeled sample is stored as `docs/l1_muestra_200.csv`.
*   **Deliverables:** `internal/regex/` (parser, AST, Thompson, simulator), `internal/lexer/` (normalize, tokenizer, stoplist, symtab, ER generator, prefix index), `cmd/simulador/`, populated `resultados.db`, vocabulary/DF export file, `internal/lexer/stoplist/v1.json` (versioned stoplist), `docs/PLAN_PRUEBAS.md`, `gold5.json` (candidates; frozen after Phase 3), `docs/l1_muestra_200.csv` (labeled L-1 sample), ADR-003 (direct NFA simulation over DFA subset construction), ADR-008 (restricted tilde-less stoplist variants; no global accent folding).
*   **Testing Focus:** **Level 1 Unit (CPU01–CPU13, plus CPU14):** parser nominal/error/precedence/deep-nesting; Thompson fragment state/transition counts; simulation accept/reject and empirical O(n·m) probes (10/100/1k/10k chars); symbol-table counters; stoplist filter/retain cases — CPU11–CPU13 and CE-7 execute against the versioned stoplist file; sweep persistence test: the sweep never inserts a `frecuencias` row with `valor = 0` (it would violate `CHECK(valor > 0)`), and zero-occurrence (lexema, categoria) pairs are represented by absence of a row, so the I-2 sums remain correct; CPU14 — a project addition **not present in Anexo II** (which ends at CPU13) and listed as an extension in `docs/PLAN_PRUEBAS.md` — asserts that "segun" and "ole" resolve to the same class as "según" and "olé" in `v1.json` (preposition and interjection respectively), with negative assertions that "él", "qué", "sí" and "té" are not filtered. **Level 2 Property-Based (CPP01–CPP04):** I-1 round-trip **0 failures** over the full catalog; I-2 frequency conservation via the corrected query — `GROUP BY l.id, f.corrida_id … HAVING global != suma_categorias` — returning **0 rows** (**deviation from baseline §6.3.3**, which grouped by `l.id` only and summed across corridas); I-3 idempotence — two runs, identical **SHA-256** of `resultados.db`; I-4 linearity — sweep 1k/10k/30k/50k/73k, **R² ≥ 0.99**, T(73k) **< 60 s**. **Level 3 Equivalence/Boundary (CPE01–CPE04):** CE-1…CE-7 (stopword-only → null vector; single token; empty text; emojis/URLs/HTML as separators; >1,000-char text; homographs retained) plus boundary lengths 0/1/2/999/1000/1001/10000 and counter-overflow probes. **Level 4b/4c Integration:** no orphan lexemes, every lexeme has ≥1 variant, every stored ER parses; 100-comment gold corpus oracle. Coverage gate **≥ 80%** (`go test -cover`). Document validation (A1): every threshold in the Phase 5 final acceptance checklist appears in `docs/PLAN_PRUEBAS.md`. Limitation measurements: L-2 — fraction of catalog lexemes with a single observed variant (baseline §6.3.10/§7.3) — is computed and reported; L-1 (under-/over-filtering rates from the labeled 200-token sample) and L-2 are required sections of `docs/PLAN_PRUEBAS.md`. Anexo II row→phase mapping (each row in exactly one phase): CPU01–CPU13, CPP01–CPP04, CPE01–CPE04 → Phase 2; CPA06, CPM01, CPM02 → Phase 3; CPA01–CPA05 → Phase 4; CPU14 is a project extension outside Anexo II, listed in `docs/PLAN_PRUEBAS.md` and executed in Phase 2.

**Phase 3 — ML Training (Python) & JSON Porting (Go)**
*   **Tasks:** Create isolated Python venv (scikit-learn); export corpus using the deterministic 80/20 temporal-stratified split fixed and persisted in Phase 1 (no re-splitting; no temporal leakage); build the parity harness — Python vectorizer invokes the **Go tokenizer as subprocess** so both sides share one lexical definition; compute TF-IDF with vocabulary and IDF derived from the training partition only (Phase 2 train-partition DF export; df=0-in-training terms excluded from the model vocabulary and counted in the evaluation report), L2 normalization; train **NBM** and **Softmax LR** under the three imbalance strategies (class weights / oversampling / baseline) with **5-fold stratified CV**; select winner by mean Macro-F1; final evaluation on the held-out test set (Macro-F1, per-class recall, row-normalized confusion matrix); freeze the final gold5 after model selection under the stated criterion (winning-model-correct, confidence ≥ 0.80 — threshold fixed in Phase 2); export `modelo.json` — sparse index–value weights, bias vector, IDF vector, vocabulary map, embedded CV metrics — plus `modelo_alternativo.json` for the oral-defense comparison; implement `internal/ml`: JSON loader and inference (tokenize → vocab map → sparse TF-IDF → per-class `z_k = b_k + Σ w_{k,i}·x_i` over the support only → softmax with max-subtraction → top-5 lexemes by `|w_{k,i}·x_i|` for explainability).
*   **Deliverables:** `ml/` Python package (train/evaluate/export), `modelo.json`, `modelo_alternativo.json`, frozen `gold5.json`, `internal/ml/` (loader + inference), evaluation report (CV table, confusion matrix), ADR-004 (model choice, JSON-over-pickle rationale).
*   **Testing Focus:** **Level 5 Python↔Go Parity (CPA06):** 1,000 random test comments vectorized on both sides — sparse vectors identical (**L1 = 0**); the 5 gold demo comments (frozen `gold5.json`, drawn from the Phase 1 test partition and finalized after model selection) yield identical predicted categories in both runtimes; Go inference unit tests against Python-precomputed fixture scores (tolerance-defined float comparison). Acceptance gates: **Macro-F1 ≥ 0.85 (CPM01)**, **minority-class recall (Reconocimientos) ≥ 0.70 (CPM02)**.

**Phase 4 — Web Service & Integration** *(consigna e)*
*   **Tasks:** Implement `cmd/autoatend`: stdlib `net/http` bound to `127.0.0.1`, port 8471 with fallback scan 8472–8480 and console banner showing the effective URL; handlers for the five endpoints with strict input validation (empty `texto` → 400 with descriptive message; oversize body → 413; SQL-injection-safe by construction — read-only DB, parameterized-only queries); `/api/health` returns exactly `{"ok": true, "version": "...", "lexemas": N, "puerto": P}`; pagination on `/api/lexemas`; `go:embed` of DBs, model, frozen `gold5.json`, and single-file HTML UI; startup DB loader per embedded database: `sql.Open("sqlite", ":memory:")` → pool pinned (`SetMaxOpenConns(1)`, `SetMaxIdleConns(1)`, `SetConnMaxLifetime(0)`, `SetConnMaxIdleTime(0)`) → `Conn.Raw` + `Deserialize(embeddedBytes)` → `PRAGMA query_only=ON`, with a non-nil `Deserialize` error fatal at startup (no temp files are written); response schema `{"categoria", "confianzas"{5}, "lexemas_clave"[5]}` with confidences summing to 1.0; implement `--selftest` (<3 s: integrity/count check of `corpus.db`, ER-syntax validity of the `resultados.db` catalog, classification of the 5 embedded gold comments against expected labels, port availability/fallback check → exit 0/1 with per-check diagnostics); the gold-comment check is a **regression guard** (gold5 was selected as correctly classified by the winning model), not independent accuracy evidence — accuracy is attested only by CPM01/CPM02 on the full test partition; pre-gate review task: confirm the implemented parity and API tests match `docs/PLAN_PRUEBAS.md` before the Phase 5 gate.
*   **Deliverables:** `internal/web/` (handlers, middleware, banner), `cmd/autoatend/` main, embedded UI, `--selftest` mode, ADR-005 (loopback-only, no TLS/auth/CORS), ADR-007 (embedded DBs via `Deserialize`; `journal_mode=DELETE` pre-embedding; per-database runtime integrity).
*   **Testing Focus:** **Level 6 API Contract (CPA01–CPA05):** valid classify → 200 with 5 confidences summing to 1.0; empty text → 400, no panic; 1 MB body → 413 or <50 ms; SQLi payload → 200/400 with `resultados.db` unmodified; `/api/lexemas` field shape; `/api/categorias` exactly 5; `/api/health` asserts all four contract fields (`ok=true`, `version`, `lexemas`=N, `puerto`=P); occupied-8471 → binds 8472 with correct banner. **Latency test:** 100 consecutive `/api/clasificar` calls, **P99 < 50 ms**. Handler tests via `net/http/httptest`; `--selftest` exit-code tests. **Startup spike (pass/fail):** pass iff (a) `Deserialize` succeeds on the exact embedded images (both built with `journal_mode=DELETE` before `VACUUM`/embedding); (b) `--selftest` completes < 3 s with the real-size DBs; (c) peak RSS is measured and reported (expected ≈ 2× DB size — embed region + SQLite buffer — far under the 8 GB budget); (d) the I-3 SHA-256 is computed on the generated `resultados.db` file before embedding, never on a runtime buffer; the fallback, used only if the spike fails: extract the embedded DB bytes to a file in the user temp directory and open it read-only. **Level 4 end-to-end re-run** of the full chain `gencorpus → corpus.db → simulador → resultados.db → modelo.json → inference` on a clean checkout.

---

**Sequencing rationale:** the phases form the critical path dictated by data flow — no lexeme catalog → no TF-IDF matrix → no model → no inference — so they must run strictly in order, with each phase's invariant gates acting as the entry criteria for the next (e.g., Phase 3 cannot start until I-1/I-2 pass on `resultados.db`). Phase 3's actual dependencies on Phase 2 are the train-partition document-frequency export and the I-1/I-2 gates on `resultados.db`. In addition, the gold5 candidates authored in Phase 2 are drawn from the Phase 1 test partition and are frozen only after Phase 3 model selection, and Phase 4's `--selftest` depends on the frozen set.
